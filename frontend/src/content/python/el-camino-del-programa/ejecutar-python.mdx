# Ejecutar Python

Python ofrece **dos modos de ejecución** con comportamientos distintos: interactivo y script. Elegir uno u otro depende del contexto de uso y afecta directamente a cómo se evalúan y muestran los resultados.

---

<Callout type="recuerda">
  En **1.1 ¿Qué es un programa?** vimos que Python ejecuta las instrucciones siguiendo un **flujo de control**, de arriba a abajo salvo que un condicional o una repetición lo altere. Ese mismo flujo secuencial es el que sigue un script — la diferencia está en cuándo y cómo se muestra cada resultado.
</Callout>

### REPL: Read-Eval-Print Loop

**REPL** son las siglas de *Read-Eval-Print Loop*: el intérprete **lee** una expresión, la **evalúa**, **imprime** el resultado y repite el ciclo. Cada expresión introducida produce salida inmediata, sin necesidad de `print()`.

### Diferencia clave entre modos

- En el **REPL**, toda expresión evaluada produce salida automáticamente.
- En **modo script**, solo las expresiones pasadas explícitamente a `print()` generan salida visible. El resto se evalúa "en silencio".

<Callout type="error-comun">
  Probar una línea suelta en el REPL y ver que "funciona" no garantiza nada sobre cómo se comportará dentro de un script. Es habitual copiar una expresión que funcionaba en el REPL a un archivo `.py`, ejecutarlo y no ver ninguna salida — porque en modo script hace falta `print()` explícito.
</Callout>

<Callout type="contexto-profesional">
  En el día a día profesional, el REPL (o su equivalente, un notebook) se usa para explorar datos, probar una función aislada o depurar rápido, mientras que el código que se entrega o se despliega siempre vive en scripts o módulos. Saber cuándo usar cada modo —y no confundir uno con otro— es parte de trabajar con un flujo de desarrollo ordenado.
</Callout>

## Código de ejemplo

### REPL en acción

```python
>>> 2 + 2
4
>>> "Hola" + " mundo"
'Hola mundo'
>>> type(3.14)
<class 'float'>
```

### Salida de expresiones en modo script

<CodeRunner language="python" title="Salida de expresiones en modo script" initialCode={`# En el REPL, esta expresión produce salida automáticamente:
# >>> 2 + 2
# 4

# En modo script, la expresión se evalúa sin producir salida:
2 + 2

# La salida requiere el uso explícito de print():
print(2 + 2)   # 4`} />

### Ejecutar un script desde la terminal

```
python3 mi_programa.py
```

El intérprete procesa el archivo `.py` de forma secuencial, ejecutando cada instrucción de arriba a abajo.

### Verificar la versión de Python

Desde la terminal:

```
python3 --version
```

Desde el propio intérprete, el módulo `sys` expone información detallada:

<CodeRunner language="python" title="Verificar versión desde el intérprete" initialCode={`import sys

print("Versión:", sys.version)
print("Versión principal:", sys.version_info.major)   # devuelve 3 en Python 3.x`} />

<Callout type="pro-tip">
  Cuando algo falla y no sabes si es un problema de tu código o del entorno, comprobar `sys.version_info` es de los primeros pasos que da cualquier profesional: muchas librerías y funciones dejan de estar disponibles —o cambian de comportamiento— entre versiones de Python.
</Callout>

## Buenas prácticas / errores comunes

- **`command not found: python3`** — indica que el ejecutable no está registrado en el `PATH` del sistema. Verifica la instalación o usa el comando correcto para tu plataforma (`python` en algunos sistemas Windows, `python3` en macOS/Linux).
- **Usa el REPL para explorar, no para programas finales.** Es ideal para probar una función o inspeccionar un valor, pero el código destinado a reutilizarse debe vivir en un archivo `.py`.
- **Verifica la versión antes de depender de sintaxis reciente.** Algunas funcionalidades de Python solo existen a partir de ciertas versiones (`3.10+`, `3.12+`, etc.); comprobar `sys.version_info` evita errores en otros entornos.

> Los errores más frecuentes durante la ejecución de programas —de sintaxis, de ejecución y semánticos— se tratan en detalle en la sección **1.7 Depuración**.
