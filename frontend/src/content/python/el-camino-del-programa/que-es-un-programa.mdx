# ¿Qué es un programa?

Un **programa** es una secuencia de instrucciones que le indica al ordenador cómo realizar una tarea: resolver una ecuación, buscar texto, procesar una imagen. Su función es descomponer un problema complejo en pasos simples y ejecutables. Este apunte presenta un modelo mental sencillo para clasificar esas instrucciones y entender cómo fluye la ejecución de un programa.

### Flujo de control

Por defecto, Python ejecuta las instrucciones **de arriba a abajo**, en el orden en que aparecen. A esto se le llama **flujo de control**.

- Las instrucciones **condicionales** y de **repetición** pueden alterar ese orden.
- El ordenador aplica cada instrucción **exactamente como está escrita**, sin interpretar intenciones más allá del código.

<Callout type="error-comun">
  Los principiantes suelen leer el código como una lista plana, de arriba a abajo, incluso cuando hay un `if` o un `for` de por medio. En cuanto aparece una instrucción condicional o de repetición, hay que "seguir" el flujo real de ejecución mentalmente — no basta con leer las líneas en orden de aparición.
</Callout>

### Analogía: el programa como receta

Pensar en una receta de cocina ayuda a fijar la idea:

<table>
  <thead>
    <tr>

      <th>Programa</th>
    </tr>
  </thead>
  <tbody>
    <tr><td>Ingredientes</td><td>Datos de entrada</td></tr>
    <tr><td>Pasos numerados</td><td>Instrucciones en orden</td></tr>
    <tr><td>"Si no tienes X, usa Y"</td><td>Instrucción condicional</td></tr>
    <tr><td>"Repite durante 5 minutos"</td><td>Instrucción de repetición</td></tr>
    <tr><td>Plato final</td><td>Resultado o salida</td></tr>
  </tbody>
</table>

> **Diferencia clave**: una receta admite cierto margen de interpretación. Un programa es **determinista** — dadas las mismas entradas, siempre produce el mismo resultado.

<Callout type="pro-tip">
  Antes de escribir la primera línea de código, muchos profesionales esbozan el problema en estos términos: "¿qué entra?, ¿qué sale?, ¿qué pasos hay en medio?". Pensarlo como una receta —en papel o en pseudocódigo— ahorra tiempo de depuración más adelante, porque el diseño del flujo queda claro antes de lidiar con la sintaxis.
</Callout>

## Código de ejemplo

### Ejecución secuencial

El caso más simple: instrucciones que se ejecutan una tras otra, en orden.

<CodeRunner language="python" title="Ejecución secuencial" initialCode={`print("Primero")   # se ejecuta 1º
print("Segundo")   # se ejecuta 2º
print("Tercero")   # se ejecuta 3º`} />

Cambiar el orden de las líneas cambia el resultado del programa.

### Combinando varios tipos de instrucciones

Este ejemplo mezcla **operaciones**, un **condicional** y una **repetición** en un mismo bloque:

<CodeRunner language="python" title="Varios tipos de instrucciones" initialCode={`numero = 7  # dato de entrada (definido directamente en el código)

if numero < 1:
    # condicional: se ejecuta solo si numero < 1
    print("Número fuera de rango.")
else:
    # repetición: recorre del 1 al número indicado
    for i in range(1, numero + 1):
        cuadrado = i ** 2   # operación: cálculo del cuadrado
        print(i, cuadrado)  # salida: muestra el resultado`} />

**Salida esperada:**

\`\`\`
1 1
2 4
3 9
4 16
5 25
6 36
7 49
\`\`\`

## Buenas prácticas / errores comunes

- **El ordenador no infiere intenciones.** Si el código no contempla un caso (por ejemplo, un `numero` negativo sin `if` que lo controle), el programa no lo "adivinará": hará exactamente lo que está escrito, aunque el resultado no tenga sentido.
- **Verifica el determinismo como herramienta de depuración.** Si un mismo programa da resultados distintos con la misma entrada, el problema no está en el modelo de instrucciones — probablemente hay una dependencia externa (aleatoriedad, hora del sistema, estado no controlado) que rompe esa garantía.
- **Clasifica antes de escribir.** Antes de programar una tarea nueva, identifica qué entra (entrada), qué sale (salida) y qué transformación conecta ambas (operaciones/condicionales/repetición). Ayuda a estructurar el código antes de escribir la primera línea.
